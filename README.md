# 人格偏好探索 · 正向日常签

原生微信小程序 MVP，WXML / WXSS / JavaScript / JSON，无第三方运行依赖、无后端。正式产品名称待确定，界面优先使用功能描述。测试仅供自我探索参考，非 MBTI 官方认证测试、医学诊断或职业能力评定；抽签仅为趣味正向祝福。

## 已实现

- 三个 Tab：测试、抽签、我的；默认进入测试。
- 160 道原创生活情境题，四维各 40、正反方向各 20；24/60 模式分层抽题，近期题目避让、配额回退提示、逐题自动保存及恢复。
- 五档作答、反向计分、归一化四维倾向、16 型完整独立报告。
- 300 条原创正向签文，六类各 50，独立解读；本地日期防重，前三百抽优先不重复，连续五抽优先不同类别，次数不限。
- 32 种人格分享卡 / 24 种抽签分享卡；Canvas 2D 动态文本与本地插画、预览、切换、PNG 导出、主动保存到相册。
- 分享小程序页面和保存竖版海报分开处理；共享页面不依赖收件人的本机记录，不传个人答案和得分，不绘制假小程序码。
- 测试、抽签、卡片生成历史各最多 30 条；支持删除单条、二次确认清空、空状态。

## 微信开发者工具导入

1. 获取本仓库，打开微信开发者工具，选择“导入项目”。项目目录指向本 README 所在目录。
2. `project.config.json` 的 `appid` 为明确的测试占位配置 `touristappid`，不是正式 AppID。可使用开发者工具提供的测试/无 AppID 模式；若当前工具不允许该模式，使用你自己的测试号 AppID。
3. 获得真实 AppID 后替换 `project.config.json` 中 `appid`；无需改动业务代码。不要把 AppSecret 写入仓库。
4. 选择稳定的基础库，建议 2.30.0 或以上，需支持 Canvas 2D 与离页提醒接口。正常编译默认进入测试 Tab。
5. 在工具的模拟器验证流程；正式预览、分享、相册权限与发布能力需要你自己的有效 AppID、账号权限及实际设备。

本项目没有需要启动的 Node 服务，也无需 `npm install`。`package.json` 仅组织 Node 内置测试命令。测试配置不能证明正式微信分享或上线能力可用。

## 目录

- `pages/`：10 个页面，每页具有 JS / JSON / WXML / WXSS。
- `data/questions.js`：160 道题；`profiles.js`：16 型报告；`fortunes.js`：300 条签文；`share-themes.js`：56 种模板映射。
- `services/quiz-engine.js`：选题与计分纯函数；`fortune-engine.js`：日期、防重、类别与模板避让。
- `services/storage.js`：统一版本化本机存储；`poster-renderer.js`：Canvas 图像加载、换行、布局与导出。
- `assets/`：16 张本地程序绘制场景、6 个统一线条 Tab 图标、两张生成式插画主视觉。
- `tests/`：数据、算法与页面逻辑集成检查。测试中的微信 API 是模拟实现，不能取代微信编译及真机验收。

## 算法与边界

每维得分为 `sum(polarity * (answer - 3)) / (2 * 完成题数) * 100`，显示值四舍五入到整数。正数倾向 E/S/T/J，负数倾向 I/N/F/P；绝对值小于 15 标为接近均衡。恰好为零固定选该维第一个字母，同时明确显示不确定性，不使用随机边界；全中立字母为 ESTJ，仅为展示规则，并非确定结论。四维百分比是两侧倾向的展示转换，不是准确率。

60 题四维的正向配额交替为 8/7/8/7，反向为 7/8/7/8。每四题包含四个维度，场景随候选题随机交错；场景分布为软目标，不牺牲维度配额。抽题时保存固定 ID 数组及回答，恢复不会重新抽题。

最近题目最多记录 120 个 ID。历史上限 30 不限制当天防重：独立保存当天最多 300 个已抽 ID，抽完一轮才开始新一轮。设备本地日期变化即开启新的一天，不声称服务器时间同步。类别避让近期四类，池不足时回退到仍未抽过的候选；模板避让最近三种。

存储版本为 1，兼容字符串化的旧存储形态并补齐缺省字段；损坏或未知版本返回安全空状态，不对未知数据做猜测转换。无云同步。卸载、清理微信数据、换设备都会影响记录。写入失败显示提示，不将未落盘的答题作为成功完成。若将来升级 schema，应在 storage 层加入显式版本迁移。

## 分享卡与资源维护

“我的卡片”记录生成内容 ID 和模板 ID，重新打开时重绘；不长期保存导出的临时文件，不代表已经分享到微信。保存到相册的文件由用户管理，删除本地历史不会删除系统相册图片。

人格 A/B 分别采用风景大字卡和侧景分区卡；每型配色与场景映射不同。抽签六组配色，各有四种画面/信息位置不同的版式。海报为 600 × 1000，导出 PNG，按 Canvas 实测文字宽度换行；超出允许行数显式报错，避免截字。原生分享入口发送内容页面，不自动发送竖版图片，也不自动发布朋友圈。朋友圈入口是否出现须在正式 AppID 与真机验证。

两张主视觉按上传参考的色彩和构图方向新生成，无文字、二维码、品牌或个人身份信息；其余场景与图标为本项目程序绘制。资源都在本地，不依赖网络图库。生产使用前请人工审阅生成素材的质量与使用范围。替换资源时保留路径和扩展名，或同步修改页面及 poster-renderer 的加载路径；尽量控制整个主包在平台当前限额内。

名称集中在 `app.js` 的 `globalData.productName`；当前来源标识是“人格偏好探索 · 正向日常签”。确定正式名称后可统一调整 app 配置、关于说明、海报来源和分享标题，无需改算法。当前不申请微信昵称、头像、定位、通讯录或手机号权限；相册权限仅在主动保存时处理。

## 首版限制

当前云机器没有微信开发者工具或真实微信设备，因此尚未完成微信编译、视觉适配、相册写入、真实分享、朋友圈入口或审核验证。测试配置只用于导入调试；正式 AppID、名称查重、类目和隐私审核、上线发布由项目所有者办理。首版不含登录、同步、收藏体系、意见反馈后端、付费、广告或真实小程序码。Canvas 与页面体验应按报告在微信中实测后再发布。
